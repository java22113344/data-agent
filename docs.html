Installation

DataAgent for Windows is delivered as a single signed installer. Download DataAgent-Setup.exe from the download page, run it, and open DataAgent from the Start Menu. The application runtime, analytics engine, and interface are packaged inside the executable, so nothing has to be prepared beforehand. The one optional extra download is the local model used for AI chat — see AI Setup on the download page; SQL, Excel, dashboards and exports need no model at all.

Installer DataAgent-Setup.exe (roughly 300–400 MB — see the release page for the exact size) Installs to C:\Program Files\DataAgent Shortcuts Start Menu — DataAgent, DataAgent (web) Portable build DataAgent.exe — runs from any folder, no install First account Created by the operator — there is no built-in default

When the wizard finishes, DataAgent opens its workspace automatically. Choose your AI provider in Settings and the platform is ready for your first dataset.

Overview

DataAgent is an AI-powered data analytics platform for Windows. It combines a FastAPI service layer, an embedded DuckDB analytics engine, and your choice of large language model into one desktop application for asking questions, writing SQL, building dashboards, and exporting results.

The application runs entirely on your machine. Datasets, dashboards, and credentials stay in the local workspace; nothing is transmitted anywhere unless you connect a cloud model provider yourself. Release quality is verified by the project's own automated test suite — a pytest suite that runs on every change, with a coverage gate enforced in CI (see pyproject.toml). It is the same suite a reviewer can run locally, so there is no separate "product accuracy" number to trust.

Architecture

The platform is organised into three layers:

⚙

Service Layer

Application services with REST endpoints for chat, SQL, data management, authentication, and export

🖨

Analytics Engine

Embedded DuckDB warehouse for SQL execution, data profiling, pipelines, and aggregation

🤖

AI Layer

Multi-provider model integration with Ollama, OpenAI, Anthropic, Gemini, and more

Configuration

Settings are managed in the application under Settings, and stored in config/settings.yaml for administrators who prefer file-based management:

# config/settings.yaml app: name: "DataAgent" version: "1.0.0" port: 8002 database: engine: "duckdb" path: "data/warehouse.duckdb" backup_enabled: true auth: enabled: true secret_key: "auto-generated" session_ttl_hours: 72 llm: provider: "ollama" # ollama | openai | anthropic | gemini model: "qwen2.5:7b" temperature: 0.3 max_tokens: 4096

A fresh install ships with no built-in account — no default email, no default password. The first account is created by the operator, and that first registrant becomes the admin. Creating it over HTTP requires the DATAAGENT_BOOTSTRAP_TOKEN environment variable; with no token configured, the first admin cannot be registered over HTTP at all and must be provisioned out of band (see docs/OPERATIONS.md and docker-compose.yml). Every later account registers as a standard, least-privilege user unless an existing admin grants more.

AI Providers

Ten model providers are supported. Choose one during setup or switch at any time in Settings:

  • Ollama — Local models including Qwen 2.5, LLaMA 3, Mistral, and Phi-3. Detected automatically once running; no configuration required. The model is pulled once (about 4.7 GB for qwen2.5:7b) from the Ollama settings panel or with ollama pull.
  • OpenAI — GPT-4o and GPT-4o-mini. Requires an API key.
  • Anthropic — Claude 3.5 Sonnet and Claude 3 Haiku. Requires an API key.
  • Google Gemini — Gemini 1.5 Pro and Gemini Flash. Requires an API key.
  • DeepSeek — DeepSeek Chat and DeepSeek Coder. Requires an API key.
  • Groq — LLaMA 3 on Groq hardware for low-latency inference. Requires an API key.
  • xAI — Grok-2. Requires an API key.
  • LM Studio — Desktop model server for local inference. Detected automatically once running.

API Reference

The platform exposes a documented REST API for integrations and automation:

# Authentication POST /api/auth/login # Sign in, returns token POST /api/auth/logout # End session GET /api/auth/me # Current user # Assistant POST /api/chat # Ask a question, receive an answer GET /api/chat/history # Conversation history DELETE /api/chat/history # Clear history # SQL POST /api/sql/execute # Run a query GET /api/sql/history # Query history GET /api/sql/schema # Warehouse schema # Data POST /api/data/upload # Upload CSV, Excel, or JSON GET /api/data/tables # List warehouse tables GET /api/data/profile/{table} # Column profiling # Dashboards GET /api/dashboards # List dashboards POST /api/dashboards # Create a dashboard GET /api/dashboards/{id} # Dashboard detail PUT /api/dashboards/{id} # Update a dashboard # Export POST /api/export/pbix # Power BI — returns a .pbix with data POST /api/export/pdf # PDF POST /api/export/pptx # PowerPoint POST /api/export/xlsx # Excel

The Power BI export returns a .pbix file that contains your data — star schema and DAX measures included — so it opens in Power BI Desktop with your charts already populated. DataAgent also imports existing .pbix files and Power BI templates, and rebuilds them locally.

Security

Enterprise-grade controls are included in every installation:

  • Authentication — Token-based sessions with a configurable lifetime (72 hours by default)
  • Role-Based Access — Admin, Editor, and Viewer roles with granular permissions
  • Single Sign-On — OpenID Connect and SAML 2.0 with Okta, Azure AD, and Keycloak
  • Audit Logging — Sign-ins, queries, exports, and settings changes are recorded
  • Row-Level Security — Per-role data filtering enforced by the analytics engine
  • API Key Management — Scoped keys with rotation and usage tracking
  • Data Privacy — The desktop app keeps all data local and ships no telemetry, no analytics and no crash reporting. The only outbound calls are the GitHub update check and the LLM provider you configure (see the FAQ)
