About

Analytics that stays home

We build DataAgent because the fastest way to understand your data shouldn't require handing it to someone else.

The story

Born from a blocked dashboard request

DataAgent started the way most internal tools do: a team needed answers, the cloud BI rollout was six weeks out, and the security review hadn't even started. So we built the thing we actually wanted — an agent you run yourself, over a warehouse that lives on your own disk, with a model you choose.

Today it's a full product: natural-language chat, a SQL workbench, profiling and ETL pipelines, dashboards with Power BI interop, ten LLM providers, and a web UI that feels like one. Still one Python process. Still local.

How we build

Open source, on purpose

"Local-first" is only trustworthy if you can verify it. The whole stack — FastAPI backend, DuckDB warehouse, ETL, auth, packaging — is open and inspectable. Security claims that can't be read aren't claims; they're marketing.

We ship on a steady cadence (see the changelog), keep the docs honest, and treat boring reliability as a feature.

"Your data already lives on your machine. The tools you use to understand it should too." — The DataAgent principle everything else follows from
Principles

What we optimize for

🔒
Privacy first

No telemetry, no default egress. If data leaves, you configured the destination yourself.

🔌
Show the work

Every answer exposes its SQL. An assistant you can't audit is a liability, not a feature.

⚙️
Boring by design

Single writer, parameterized queries, secrets out of git. Security that fits in one paragraph.

🎓
Open by default

Read the code, fork it, self-host it. Trust is earned in diffs, not in policy PDFs.
